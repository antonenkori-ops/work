# Work Assistant

Внутренний рабочий инструмент: Jira-дашборд, диаграммы Ганта, алерты AlertManager, генератор планов работ.
Backend — Python (FastAPI) + SQLite, frontend — React (Vite). Без Docker, всё поднимается напрямую на рабочей машине.

## Этап 1: Jira-дашборд

Что реализовано:
- Синхронизация задач и комментариев из Jira по кнопке «Обновить» (без фонового опроса).
- Локальное хранение в SQLite (`backend/work_assistant.db`, создаётся автоматически).
- Список задач в работе (не Done), сортировка по дате обновления, описание и комментарии свёрнуты по умолчанию.
- Статистика: всего выполнено / с начала года / за месяц / за неделю (по дате резолюции).

## Запуск на рабочей машине

### 1. Backend

```
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Откройте `backend\.env` и заполните:
- `JIRA_BASE_URL` — адрес вашей Jira (без слэша в конце)
- `JIRA_USERNAME` / `JIRA_PASSWORD` — логин и пароль
- `JIRA_JQL` — при необходимости поменяйте JQL (по умолчанию — ваши задачи, `assignee = currentUser()`)

Запуск сервера:
```
uvicorn app.main:app --reload --port 8000
```

Проверка: откройте в браузере `http://localhost:8000/api/health` — должно вернуть `{"status":"ok"}`.

### 2. Frontend

В новом терминале:
```
cd frontend
npm install
npm run dev
```

Откройте `http://localhost:5173`.

### 3. Проверка функциональности

1. Нажмите кнопку «Обновить» — должна пройти синхронизация с Jira (первый раз может занять какое-то время).
2. Если появилась красная плашка с ошибкой — пришлите текст ошибки, это поможет быстро найти причину (неверный URL, логин/пароль, некорректный JQL и т.д.).
3. Проверьте, что появился список задач в работе, отсортированный по дате обновления.
4. Разверните у одной из задач блок «Описание» и «Комментарии» — проверьте, что данные подтягиваются корректно.
5. Проверьте плитки статистики сверху (всего выполнено / год / месяц / неделя) — сверьте примерно с тем, что ожидаете увидеть.

Напишите, что получилось — пойдём дальше по итогу.
